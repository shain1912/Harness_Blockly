# BlockPy

A browser playground for **1:1 bidirectional, lossless conversion between Blockly visual blocks and Python text**. Edit code as blocks or as text — both stay in sync, and converting one to the other and back is lossless (comments aside). A React + Vite frontend pairs with a small Express backend that proxies AI calls.

The core is a live CPython-3.12 `ast` IR pipeline: Python text is parsed by the real `ast.parse` (running in Pyodide), serialized to a JSON IR, and mapped to/from `ir_*` Blockly blocks — the reverse direction rebuilds the ast and emits text via `ast.unparse`. Library blocks are generated by runtime introspection (blockpy-gen), not hand-written tables. Also ships as an offline Electron desktop app.

## Features

- **Bidirectional sync** — write Python or drag blocks; the other side updates live. Sugar (list comprehensions, ternaries, chained comparisons) keeps dedicated blocks; an optional Auto-Desugar pass rewrites it into elementary loop/conditional blocks.
- **Lossless round-trip** — every CPython-3.12 ast node has a block (raw=0); the round-trip contract is `ast.dump(original) == ast.dump(regenerated)`, comments included (formatting is regenerated).
- **Scratch3/MakeCode look** — Blockly's `zelos` renderer with a light theme. Dynamic-arity blocks (`print`, function calls, list/dict/set/tuple, method calls) have inline `+`/`–`/`+kw` buttons to add/remove argument slots.
- **Real Python run** — the Run button executes real local Python via the backend (`/api/run-python`, streamed output; real OpenCV, webcam, `imshow`). The packaged desktop app bundles a portable Python. Pyodide (WASM) is the in-browser conversion runtime.
- **Introspected library blocks** — `pip install` / Blockify a module and its functions, methods, constants, and properties become toolbox blocks via real introspection (blockpy-gen) — no hardcoded library tables. An AI "Curate" flow proposes a purpose-driven ★ subset tab with human preview.
- **Gray-block inspector** — lists any raw/unconverted blocks remaining after a conversion and jumps to each.

## Quick start

```bash
npm install
npm run vendor   # copy Blockly/Pyodide/FontAwesome into public/vendor (gitignored; the app loads them locally, no CDN)
npm start        # frontend (Vite :3000) + backend (Express :3001) together
```

Open http://localhost:3000.

Other scripts:

```bash
npm run dev      # frontend only (Vite :3000)
npm run server   # backend only (Express :3001)
npm test         # Playwright e2e (auto-starts the Vite dev server)
```

### AI features (optional)

The backend proxies AI calls to MiniMax via the Anthropic SDK (`https://api.minimax.io/anthropic`). Put one or more keys in `.env` as `MINIMAX1`..`MINIMAX4` (round-robin pool). Without keys, everything except the AI endpoints still works — running Python (`/api/run-python`), blockify introspection, type inference, file I/O, `/api/health`; the AI endpoints (`/api/ai-normalize`, `/api/ai-abstract`, `/api/ai-chat`, `/api/abstract-library`) return 503 or fall back to the heuristic desugarer.

## Architecture

### Conversion core (`src/utils/*.js`)

These files are imported by `src/main.jsx` **for side effects** — each attaches a global the rest of the app calls as `window.BlockPy*` (they also `module.exports` so tests can `require()` them in Node).

| Global | File | Responsibility |
|---|---|---|
| `window.BlockPyAstBridge` | `src/utils/pyAstBridge.js` | `pythonToIR` / `irToPython`: real CPython-3.12 `ast.parse` / `ast.unparse` inside Pyodide ⇄ JSON IR (comments preserved). |
| `window.BlockPyIR` | `src/utils/irToBlockly.js` + `blocklyToIr.js` | IR → Blockly workspace JSON and back; `NODE_POLICY` covers every 3.12 ast node (raw=0); `blocklyToIr` throws on non-`ir_*` blocks. |
| — | `src/utils/irBlocks.js` | All `ir_*` Blockly block definitions. |
| `window.BlockPyIrToolbox` | `src/utils/irToolbox.js` | The toolbox, built in JS (no XML) + one dynamic category per registered library. |
| `window.BlockPyLibRegistry` / `BlockPyLibImport` | `src/utils/libRegistry.js` / `libImport.js` | Registry of introspected library calls/constants/properties; maps blockpy-gen LibrarySpecs into it. |
| `window.BlockPyIrDesugar` | `src/utils/irDesugar.js` | Optional IR→IR desugar pass (opt-in). |

`Blockly` and Pyodide are vendored into `public/vendor/` by `npm run vendor` (offline, no CDN). `src/utils/pyodideRunner.js` is the one real ES module, imported by `App.jsx`. The legacy `parser.js` / `desugarer.js` / `libraryAbstraction.js` are still loaded for side effects but are frozen and retired from conversion — see `CLAUDE.md`.

### Frontend (`src/`)

`App.jsx` owns layout and state. Left: `FileExplorer` (workspace files + Run/Save) and tabbed `VariableWatch` / `ConsoleLogs` / `LibraryManager`. Right: tabbed `BlocklyEditor` / `PythonEditor` / desugared-code preview / `ASTTreeView`. The live workspace is exposed as `window.__blocklyWorkspace`.

### Backend (`server.js`)

Express bound to **127.0.0.1** (loopback-only, with a Host-header guard). Vite proxies `/api/*` to it in dev; the packaged Electron app embeds the same `server.js` and serves the built frontend from it. Endpoints: run real Python (`/api/run-python`), pip install, blockpy-gen introspection (`/api/blockify`), Jedi type inference (`/api/infer-types`), workspace file I/O (`/api/fs/*`), and the AI proxy (normalize/abstract/curate/chat).

## Project structure

```
index.html              # app shell; loads /src/main.jsx + vendored Blockly (/vendor/blockly)

electron/main.cjs       # desktop shell: embeds server.js + bundled python-embed

scripts/                # vendor-assets.cjs (public/vendor), desktop build helpers
src/
  main.jsx App.jsx      # entry + root component
  components/           # FileExplorer, BlocklyEditor, PythonEditor, LibraryManager, panels…
  utils/                # pyAstBridge, irToBlockly, blocklyToIr, irBlocks, irToolbox,
                        # libRegistry, libImport, irDesugar, pyodideRunner (+ frozen legacy:
                        # parser, desugarer, libraryAbstraction)
tests/                  # Playwright e2e specs + fixtures (ir_*.spec.js = live pipeline)
python.md               # Python syntax catalog (coverage reference)
block_gap_analysis.md   # audit of catalog vs. implemented blocks
DOCS/superpowers/       # design specs + implementation plans
papers/                 # background research notes (describe older designs — trust src/)
```

## Testing

App tests are Playwright e2e; `blockpy-gen/` uses Node's built-in test runner. Playwright auto-starts the Vite dev server; tests that hit backend endpoints (blockify, AI, shell run) also need `npm run server` running. The **live pipeline gate** is `tests/ir_*.spec.js` (`npm run test:ir`) plus `npm run test:gen` — these are the CI merge gates (`.github/workflows/validity.yml`). The legacy parser corpora (`npm run test:validity`) pin the frozen pre-IR path and are non-gating.

```bash
npm test                                     # everything
npm run test:ir                              # live IR pipeline (merge gate)
npm run test:gen                             # blockpy-gen engine (merge gate)
npx playwright test tests/ir_roundtrip.spec.js   # one spec
npx playwright test -g "hello world"         # one test by title
npm run test:report                          # open the HTML report
```

See `CLAUDE.md` for contributor conventions (adding blocks, field-name parity, round-trip rules).
