# 추후 계획 (로드맵): AI 라이브러리 추상화 (초등학생용) + Python 1:1 유효성 불변식

> 상태: **미래 계획(로드맵)**. 즉시 구현 대상 아님. 각 단계(P1~P5)는 별도 spec→plan→구현
> 사이클로 진행한다. 이 문서는 전체 방향과 불변식을 고정하는 기준점이다.
> 작성일: 2026-06-05.

## 1. 비전 / 문제

새 라이브러리를 설치하면 현재는 모르는 호출을 함수당 1:1 `lib_<lib>_<func>` 블록으로
매핑한다(라벨만 예쁜 사실상 1:1). 라이브러리가 크면(mediapipe, opencv, pandas…) 블록 수가
폭발하고 **초등학생에게는 너무 복잡**하다.

목표: 라이브러리를 통째로 블록화하지 말고, **AI가 소수의 초등학생용 고수준 블록으로
추상화**한다(예: mediapipe 손추적 수십 줄 → "손 인식하기" 블록 하나). 동시에 BlockPy의 핵심
가치인 **Python ↔ 블록 1:1 무손실 변환 유효성은 그대로 유지**한다.

핵심 긴장: 추상 블록 1개 = Python 여러 줄이라 본질적으로 1:1을 넘어선다. 해소책은 추상화를
**오서링 매크로**로 한정하고, 1:1 무손실은 **코어 파서의 불변식**으로 분리·강제하는 것이다.

## 2. 핵심 아키텍처 — 2계층

### A. 코어 계층 (불변식, 변경 금지 대상)
기존 `src/utils/parser.js`의 Tokenizer/Parser/`astToPython`/`astToBlockly`/생성기.

**불변식 (Invariant-1):** 임의의 유효 Python → 블록 → Python 은 무손실이다(주석 제외,
설계상 허용된 의미동형 정규화 제외). 모르는 라이브러리 호출은 1:1 `lib_<lib>_<func>`
블록으로 떨어지고 원문을 그대로 재생성한다.

이 계약은 추상화 기능이 **절대 깨뜨릴 수 없다**. 추상화는 코어 위에 *덧붙는* 계층이지,
코어를 바꾸지 않는다.

### B. 추상화 계층 (덧붙이는 오서링 팔레트)
AI가 라이브러리당 생성하는 **매크로 블록** 소수(권장 2~6개). 각 매크로 블록의 정의:

- **표시**: 초등학생용 이름(한글 라벨), 아이콘, 단순 입력 슬롯.
- **정규 Python 템플릿**: `{slot}` 구멍을 가진 멀티라인 Python 스니펫.
- **생성기 (block → Python)**: 슬롯 값으로 템플릿을 확장해 여러 줄 Python을 emit.
- **단방향(오서링 전용)**: 끌어다 쓰면 Python을 만든다. **Python → 매크로 역붕괴는 하지
  않는다** — 그 Python은 코어 1:1 경로로 평범한 블록들로 round-trip 된다. 따라서 손실 0,
  깨지기 쉬운 패턴매칭 불필요.
- **저장 단위**: 검토를 거친 **프리셋**(JSON). 현재 `libraryAbstraction.js`의 `AI_PRESETS`
  패턴을 확장한다.

**불변식 (Invariant-2):** 매크로의 정규 Python 템플릿은 그 자체로 코어 파서가 파싱·무손실
round-trip 가능한 Python이어야 한다. → 매크로가 코어가 다루지 못하는 Python을 만들 수 없다.

> 결과적으로 "추상 vs 1:1"의 긴장은 사라진다: 추상은 *생성*만 하고, *검증·왕복*은 항상
> 코어 1:1 경로가 책임진다.

## 3. AI 생성 → 큐레이션 → 저장 파이프라인

1. **생성**: 설치 시 `/api/ai-abstract`가 모델에 "이 라이브러리의 고효용 초등학생용 블록
   소수"를 요청한다. 각 블록 = `{ name(한글), slots:[{id,label,type,default}], pythonTemplate,
   icon, colour, category }`. 모델은 라이브러리 핵심 사용 시나리오를 소수의 블록으로 압축한다
   (현재 AI_PRESETS의 "Abstraction Strategy" 노트 — requests→GET/POST, pandas→CSV읽기+describe
   — 와 동일 철학).
2. **큐레이션 (사람 게이트)**: 큐레이션 UI가 후보 블록을 보여준다. 교사/개발자가 이름·아이콘·
   슬롯·템플릿을 편집하고, 부적절한 블록을 제거하고, 승인한다. 초등학생 대상 품질·안전을 사람이
   보증한다.
3. **저장**: 승인본을 프리셋 JSON으로 저장 → `LibraryAbstractionEngine`이 등록 → 툴박스의
   해당 라이브러리 카테고리에 노출. 저장 시 **유효성 검사(섹션 4)** 를 통과해야만 커밋된다.

## 4. 1:1 유효성 검사 (자동 하니스)

세 층위로 강제한다.

1. **코어 불변식 회귀 (Invariant-1)**: 기존 순수-Node round-trip 코퍼스
   (`tests/random_roundtrip.spec.js`, `tests/realistic_roundtrip.spec.js`,
   `tests/method_def.spec.js`)가 권위 있는 무손실 게이트다. 새 블록/추상화/프리셋이 추가될
   때마다 실행해 코어 1:1 경로가 무결함을 증명한다. CI 게이트.
2. **매크로 템플릿 검사 (Invariant-2)**: 프리셋 저장 시 각 매크로의 `pythonTemplate`(슬롯에
   샘플 값 주입)을 코어 파서로 파싱·`astToPython` round-trip 해 무손실인지 확인한다. 실패하면
   저장을 거부한다.
3. **매크로 왕복 안정성**: 매크로 블록 → Python → (코어로) 블록들 → Python 이 안정적(idempotent)
   인지 확인한다. 매크로가 만든 Python을 코어가 다시 블록화해도 의미가 보존됨을 보장.

> "여전히 Python 1:1 변환 유효성 검사"의 구체 형태가 이 하니스다 — 추상화 기능이 늘어나도
> 핵심 보장이 회귀하지 않도록 자동으로 지킨다.

## 5. 단계별 로드맵 (서브프로젝트 분해)

각 단계는 독립적으로 동작·테스트 가능한 산출물을 낸다. 순서대로 별도 spec→plan→구현.

| 단계 | 산출물 | 핵심 검증 |
|---|---|---|
| **P1 매크로 블록 모델** | `registerBlock`(또는 신규 `registerMacroBlock`)에 멀티라인 `pythonTemplate` + 타입드 슬롯 + 단방향 생성기 지원. 프리셋 스키마 확정. | 매크로 템플릿 round-trip(Invariant-2) 테스트. 기존 회귀 무영향. |
| **P2 AI 생성 엔드포인트 업글** | `/api/ai-abstract`가 라이브러리 → `{name, slots, pythonTemplate, icon, colour}` 블록셋(소수)을 제안. 프롬프트에 "초등학생용·고수준·소수" 제약. | 생성 결과가 P1 스키마에 맞고, 각 템플릿이 유효성 검사 통과. |
| **P3 큐레이션 UI** | 후보 블록 검토/편집/제거/승인 → 프리셋 저장 플로우(React 패널). 저장 시 유효성 게이트. | 승인→저장→툴박스 등록 e2e. 잘못된 템플릿 저장 거부 e2e. |
| **P4 유효성 하니스 / CI** | 섹션 4의 3층 검사를 테스트 스위트로 정식화 + 새 라이브러리 예제 코퍼스 추가. | 코어 코퍼스 + 매크로 검사 그린이 머지 게이트. |
| **P5 초등학생 폴리시** | 한글 라벨·아이콘·카테고리·난이도 레벨(초급/심화). 프리셋 i18n. | 시각·UX 확인(스크린샷), 한글 라벨 e2e. |

## 6. 리스크 / 오픈 이슈

- **AI 템플릿 품질**: 모델이 부정확/비파이썬 템플릿 생성 가능 → 큐레이션 게이트 + 자동 유효성
  검사로 차단(저장 거부).
- **슬롯 타입**: 숫자/문자열/색/드롭다운 등 슬롯 타입과 Blockly 입력 매핑 규약 필요(P1에서 확정).
- **보안**: 매크로 템플릿은 사용자/AI가 만든 Python을 실행 경로(Pyodide/Shell)에 넣는다 →
  실행 엔진의 기존 샌드박스 경계 안에서만, 큐레이션 사람 검토를 신뢰 경계로.
- **현지화(한글)**: 라벨/카테고리 i18n 구조(P5). 코드 생성은 영어 Python 유지.
- **프리셋 버전관리**: 라이브러리 버전별 프리셋 차이, 프리셋 스키마 마이그레이션.
- **역붕괴 미지원의 UX**: 손으로 쓴 라이브러리 코드는 매크로가 아니라 1:1 블록으로 보인다 —
  의도된 동작이나 사용자에게 "왜 추상 블록이 안 나오지?"가 될 수 있음 → 안내 필요.

## 7. 비목표 (현 시점)

- Python → 추상 매크로 자동 역매칭(역붕괴). 깨지기 쉬움 → 단방향 오서링으로 한정.
- 코어 파서/생성기의 1:1 계약 변경. 추상화는 항상 *덧붙임*.
- 라이브러리 전체 API의 블록화. 소수 고수준 블록만.

## 부록: 기존 자산 재사용

- `src/utils/libraryAbstraction.js` — `LibraryAbstractionEngine.registerBlock` / `AI_PRESETS`:
  P1 매크로 모델·프리셋의 출발점.
- `server.js` `/api/ai-abstract`: P2 업글 대상.
- `parser.js`의 `lib_<lib>_<func>` 동적 1:1 블록 경로: 코어 폴백(역붕괴 안 하는 임의 코드의
  무손실 경로) — 그대로 유지.
- round-trip 스위트(random/realistic): P4 유효성 하니스의 코어 게이트.
